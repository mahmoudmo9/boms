# BOMS architecture

BOMS is a modular monolith for one user on one Windows PC: one backend codebase
(FastAPI), one PostgreSQL 18 database, one background worker process from the
same codebase. No Docker, Redis, Celery or cloud services. Everything works offline.

```
backend/
  app/
    core/          shared infrastructure: config, db, secrets, security, text, money, time, web, errors
    modules/       one package per business module
      events/      core.event / core.audit, events.record()
      system/      sys.* tables: user, auth, settings, base data, jobs, backups
      documents/   core.document, core.document_link, hash-addressed file store
      search/      global search with a provider registry
    main.py        HTTP app (API + built frontend), 127.0.0.1:8765 only
    worker.py      background worker + scheduler (python -m app.worker)
    cli.py         commands used by the Windows scripts
  migrations/      Alembic revisions
  tests/
frontend/          React + TypeScript + Vite (built at release time)
scripts/windows/   install / update / backup / restore / start / stop
```

## Module rules (MUST)

- A module writes only its own tables.
- Modules interact only through each other's public service functions
  (`app/modules/<name>/service.py` or the functions a module documents as public)
  or by emitting events. No module imports another module's ORM models to write.
- Extension points for later modules:
  - jobs: `app.modules.system.jobs.register(type)` adds a job handler;
  - search: `app.modules.search.registry.register(provider)` adds a searchable entity;
  - routers are listed in `app/main.py`.
- Every state-changing service call records an event with
  `events.record(db, entity_type, entity_id, action, data, source)` using the same
  Session, so the change and its event commit or roll back together.

## Database conventions (MUST)

- Schemas: `sys, ref, core, outreach, tender, ops, fin, compliance, analytics`
  all exist from the first migration; Phase 1 only has tables in `sys` and `core`.
- Primary keys are `uuid DEFAULT uuidv7()` (generated by PostgreSQL 18).
  Append-only logs (`core.event`, `core.audit`) use `bigint` identity for ordering.
  Base data uses its natural ISO/code key.
- Every timestamp is `timestamptz`, stored in UTC. Python never uses naive
  datetimes (`app.core.time`). Conversion to local time/Jalali happens only in the UI.
- Money (later phases): `NUMERIC(18,4)` plus a currency code column referencing
  `sys.currency.code`; FX rates `NUMERIC(20,10)`. Never float. Python code uses
  `app.core.money.Money` (Decimal, rejects float).
- Every table has `created_at`; mutable tables also have `updated_at`, maintained by
  the `core.touch_updated_at()` trigger.
- Every mutable table in `sys` and `core` has the `core.audit_row(pk)` trigger,
  which writes I/U/D rows with before/after JSON to `core.audit`. New tables in
  later phases must attach it too.
- `core.event` and `core.audit` are append-only: a trigger raises on UPDATE,
  DELETE and TRUNCATE, and the app role has those privileges revoked.
- The app connects with a dedicated non-superuser role (`boms_app`) that owns the
  app schemas. The superuser is used only by install/restore scripts and tests.
- Databases are created with the builtin `C.UTF-8` locale so behaviour does not
  depend on the Windows locale.

## Text search

`core.normalize_fa(text)` (SQL, IMMUTABLE) and `app.core.text.normalize_fa` (Python)
are generated from the same character tables and tested against the same fixtures.
Every search index and every search query goes through it. Search combines
`to_tsvector('simple', normalize_fa(...))` full-text matching with `pg_trgm`
similarity; both have GIN indexes.

## Secrets

The DB password, session signing key and archive password live in Windows Credential
Manager (service `BOMS`, via `keyring`). On non-Windows dev machines and in tests,
`BOMS_DB_PASSWORD`, `BOMS_SESSION_KEY`, `BOMS_ARCHIVE_PASSWORD` environment variables
are used. No secret is stored in files, the database, logs or error messages.

## Configuration

Non-secret settings come from defaults, `<app>\boms.toml` (`[boms]` section,
written by install.ps1) and `BOMS_*` environment variables (`app/core/config.py`).
User-editable settings (backup time, secondary destination, upload limit, ...)
live in `sys.setting`.

## Security

- Uvicorn binds to 127.0.0.1:8765 only; requests whose Host header is not
  `127.0.0.1:8765` or `localhost:8765` are rejected (DNS rebinding).
- Single user, Argon2 password hash, signed HttpOnly SameSite=Strict session cookie,
  idle lock enforced on the server, double-submit CSRF token plus Origin check on
  every state-changing `/api` request, login rate limit.
